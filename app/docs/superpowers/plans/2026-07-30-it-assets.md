# IT Technician "IT Assets" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the `it_technician` role its own home with an "IT Assets" section that lists `mt_asset_list` assets category-wise (Electric Asset, IT/Communication) and lets the user add an asset into the category they are viewing.

**Architecture:** Reuse what exists. The IT home is the shared `DashboardScreen` with a one-tile config. Two new screens live in a new `presentation/it` package: a category chooser and a category-scoped asset list. Both read the register through the existing `GetMachineMasterUseCase` (`GET /mt-machines`); adding goes through the existing `MtMachineRepository.addAsset` (`POST /mt-machines`). The existing `AddMachineSheet` gains an optional locked-category mode instead of being duplicated.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), Hilt, Retrofit, Room, kotlinx-coroutines. Tests: JUnit 5 (`org.junit.jupiter`), MockK, `kotlinx-coroutines-test`.

**Spec:** `app/docs/superpowers/specs/2026-07-30-it-assets-design.md`

/**
 * Backend `mt_users.role` string -> [UserRole]. Trim + uppercase so casing or stray
 * whitespace from the API can't silently drop a user to OPERATOR. Unknown roles fall
 * through to OPERATOR (the safe, least-privileged screen) rather than crashing.
 *
 * Backend currently sends OPERATOR / TECHNICIAN / HEAD / QC / IT_TECHNICIAN; the rest
 * are legacy/local roles still used by some screens.
 */
fun parseUserRole(raw: String): UserRole = when (raw.trim().uppercase()) {
    "TECHNICIAN" -> UserRole.TECHNICIAN
    "HEAD"       -> UserRole.HEAD
    // Backend now sends a single "QC" role; treat it as QC Head so the user gets the
    // full QC inbox + actions (incl. the head-only override). Legacy QC_HEAD/QC_MEMBER
    // still map explicitly. Change "QC" -> UserRole.QC_MEMBER here if QC should be the
    // restricted (no-override) level instead.
    "QC", "QC_HEAD" -> UserRole.QC_HEAD
    "QC_MEMBER"  -> UserRole.QC_MEMBER
    "SUPERVISOR" -> UserRole.SUPERVISOR
    "ADMIN"      -> UserRole.ADMIN
    // mt_users stores 'it_technician'; the spaced spelling is tolerated in case it's
    // typed that way in pgAdmin, and bare "IT" because that's the shortest plausible value.
    "IT_TECHNICIAN", "IT TECHNICIAN", "IT" -> UserRole.IT_TECHNICIAN
    else         -> UserRole.OPERATOR
}
```

package com.candorfoods.factoryops.domain.model

/**
 * The asset categories an IT technician owns. [backendValue] is the exact
 * `mt_asset_list.category` string (the same values already listed in
 * MtMachine.kt's NON_RUNNABLE_CATEGORIES) — [label] is what the UI shows.
 *
 * Single source of truth for the IT screens: adding a third IT category is one
 * entry here and both the chooser and the list follow.
 *
 * The enum NAME (not [backendValue]) is what travels as the navigation argument —
 * "IT/Communication" contains a slash that would have to be URL-encoded and could
 * break route matching.
 */
enum class ItAssetCategory(val label: String, val backendValue: String) {
    ELECTRICAL("Electrical Assets", "Electric Asset"),
    IT_COMMUNICATION("IT / Communication", "IT/Communication");

    companion object {
        /** Parse a navigation argument. Unknown/absent falls back to the first category. */
        fun of(name: String?): ItAssetCategory =
            entries.firstOrNull { it.name == name?.trim() } ?: ELECTRICAL
    }
}

/** True when [machine] belongs to this IT category. Trim + case-insensitive, so a
 *  casing variant already sitting in the register still shows up. */
fun ItAssetCategory.matches(machine: MtMachine): Boolean =
    machine.category.trim().equals(backendValue, ignoreCase = true)
```

/**
 * IT Assets chooser: loads the asset register once and counts each IT category.
 * The full register is fetched (not one call per category) because GET /mt-machines
 * filters on an exact category string, and the counts must survive casing variants.
 */
@HiltViewModel
class ItAssetCategoriesViewModel @Inject constructor(
    private val getMachineMaster: GetMachineMasterUseCase,
) : ViewModel() {

    private val _uiState = MutableStateFlow(ItAssetCategoriesUiState())
    val uiState: StateFlow<ItAssetCategoriesUiState> = _uiState.asStateFlow()

    init { load() }

    fun onRetry() = load()

    private fun load() {
        viewModelScope.launch {
            _uiState.update { it.copy(isLoading = true, error = null) }
            when (val r = getMachineMaster()) {
                is Result.Success -> _uiState.update {
                    it.copy(isLoading = false, rows = r.data, error = null)
                }
                is Result.Error -> _uiState.update {
                    it.copy(isLoading = false, error = r.message)
                }
                is Result.Loading -> _uiState.update { it.copy(isLoading = true) }
            }
        }
    }
}

```kotlin
package com.candorfoods.factoryops.presentation.it

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import com.candorfoods.factoryops.domain.model.ItAssetCategory
import com.candorfoods.factoryops.domain.model.MtMachine
import com.candorfoods.factoryops.domain.model.Result
import com.candorfoods.factoryops.domain.model.matches
import com.candorfoods.factoryops.domain.repository.MtMachineRepository
import com.candorfoods.factoryops.domain.usecase.mtmachine.GetMachineMasterUseCase
import dagger.hilt.android.lifecycle.HiltViewModel
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update
import kotlinx.coroutines.launch
import javax.inject.Inject

data class ItAssetListUiState(
    val category: ItAssetCategory = ItAssetCategory.ELECTRICAL,
    val isLoading: Boolean = true,
    val error: String? = null,
    val rows: List<MtMachine> = emptyList(),
    val searchQuery: String = "",
    val selectedBuilding: String? = null,   // null = both / all warehouses
    val selectedFloor: String? = null,      // null = all floors / sub-locations
    val showAddSheet: Boolean = false,
    val isAddingAsset: Boolean = false,
    val addError: String? = null,
) {
    /** Register rows of this category only — every derivation below runs off this. */
    private val inCategory: List<MtMachine> get() = rows.filter { category.matches(it) }

    /** Warehouse capsule options — buildings that actually hold assets of this category. */
    val buildings: List<String>
        get() = inCategory.map { it.building }.filter { it.isNotBlank() }.distinct().sorted()

    /** Floor dropdown options, scoped to the selected warehouse. */
    val floors: List<String>
        get() = inCategory
            .filter { selectedBuilding == null || it.building.equals(selectedBuilding, ignoreCase = true) }
            .map { it.subLocation }.filter { it.isNotBlank() }.distinct().sorted()

    /** Floors present per building — feeds the add sheet so typos don't mint phantom floors. */
    val subLocationsByBuilding: Map<String, List<String>>
        get() = rows
            .filter { it.building.isNotBlank() && it.subLocation.isNotBlank() }
            .groupBy({ it.building }, { it.subLocation })
            .mapValues { (_, floors) -> floors.distinct().sorted() }

    val items: List<MtMachine>
        get() = inCategory.asSequence()
            .filter { selectedBuilding == null || it.building.equals(selectedBuilding, ignoreCase = true) }
            .filter { selectedFloor == null || it.subLocation.equals(selectedFloor, ignoreCase = true) }
            .filter { matchesSearch(it) }
            .sortedWith(compareBy({ it.building.lowercase() }, { it.assetName.lowercase() }))
            .toList()

    private fun matchesSearch(m: MtMachine): Boolean {
        val q = searchQuery.trim()
        if (q.isBlank()) return true
        return m.assetName.contains(q, ignoreCase = true) ||
            m.assetId.contains(q, ignoreCase = true) ||
            m.subLocation.contains(q, ignoreCase = true)
    }
}

/**
 * One IT category's slice of the asset register, plus adding into it. The whole
 * register is fetched and filtered in-app (rather than GET /mt-machines?category=)
 * so a casing variant already in the data still shows, and so the add sheet can
 * suggest floors from every building.
 *
 * The category is pushed in by the screen (NavGraph parses the route argument),
 * not injected — that keeps SavedStateHandle out of the ViewModel and its tests.
 */
@HiltViewModel
class ItAssetListViewModel @Inject constructor(
    private val getMachineMaster: GetMachineMasterUseCase,
    private val mtMachineRepository: MtMachineRepository,
) : ViewModel() {

    private val _uiState = MutableStateFlow(ItAssetListUiState())
    val uiState: StateFlow<ItAssetListUiState> = _uiState.asStateFlow()

    init { load() }

    /** Set the category this screen shows. Filters reset — they belong to a category. */
    fun onCategory(category: ItAssetCategory) = _uiState.update {
        if (it.category == category) it
        else it.copy(
            category = category,
            searchQuery = "",
            selectedBuilding = null,
            selectedFloor = null,
        )
    }

    fun onRetry() = load()

    fun onSearchChange(query: String) = _uiState.update { it.copy(searchQuery = query) }

    /** Switching warehouse resets the floor filter — floors are per-building. */
    fun onBuildingSelected(building: String?) =
        _uiState.update { it.copy(selectedBuilding = building, selectedFloor = null) }

    fun onFloorSelected(floor: String?) = _uiState.update { it.copy(selectedFloor = floor) }

    fun onAddClicked() = _uiState.update { it.copy(showAddSheet = true, addError = null) }

    fun onAddDismiss() = _uiState.update { it.copy(showAddSheet = false, addError = null) }

    /**
     * POST the new asset. The category is forced to this screen's category regardless
     * of what the sheet built, so an IT-added asset can never land elsewhere.
     */
    fun onSubmitNewAsset(asset: MtMachine) {
        viewModelScope.launch {
            _uiState.update { it.copy(isAddingAsset = true, addError = null) }
            val payload = asset.copy(category = _uiState.value.category.backendValue)
            when (val r = mtMachineRepository.addAsset(payload)) {
                is Result.Success -> {
                    _uiState.update { it.copy(isAddingAsset = false, showAddSheet = false) }
                    load()   // refresh so the new asset appears
                }
                is Result.Error -> _uiState.update {
                    it.copy(isAddingAsset = false, addError = r.message)
                }
                is Result.Loading -> _uiState.update { it.copy(isAddingAsset = false) }
            }
        }
    }

    private fun load() {
        viewModelScope.launch {
            _uiState.update { it.copy(isLoading = true, error = null) }
            when (val r = getMachineMaster()) {
                is Result.Success -> _uiState.update {
                    it.copy(isLoading = false, rows = r.data, error = null)
                }
                is Result.Error -> _uiState.update {
                    it.copy(isLoading = false, error = r.message)
                }
                is Result.Loading -> _uiState.update { it.copy(isLoading = true) }
            }
        }
    }
}

# Backend requirement — let `it_technician` add assets

**Requested by:** FactoryOps Android app (IT Assets feature, 2026-07-30)
**Scope:** one allow-list change. No schema change, no new endpoint.

## Context

`mt_users` already has users with `role = 'it_technician'`. The app now gives that
role an "IT Assets" section that lists `mt_asset_list` rows of
`category IN ('Electric Asset', 'IT/Communication')` and lets the user add a new
asset into the category they're viewing.

Reads already work: `GET /mt-machines` only requires an authenticated user.

## The problem

`app/api/mt_machines.py` gates creation on `_CREATE_ROLES`, which is
`SUPERVISOR / HEAD / TECHNICIAN / ADMIN`. `MtUser.norm_role` upper-cases, so an IT
user arrives as `IT_TECHNICIAN`, is not in the set, and gets:

    403 {"detail": "Not allowed to add assets"}

## The change

Add `IT_TECHNICIAN` to `_CREATE_ROLES` in `app/api/mt_machines.py`:

```python
_CREATE_ROLES = {"SUPERVISOR", "HEAD", "TECHNICIAN", "ADMIN", "IT_TECHNICIAN"}
```

Nothing else changes: `POST /mt-machines` already assigns the building-prefixed
`asset_id` server-side, stores every field, and returns the `MtMachineDto`. The app
sends `category` as the exact string `"Electric Asset"` or `"IT/Communication"`.

### Should IT be restricted to its own categories?

Your call. The app never sends anything else for this role (the category field is
read-only in the IT add form), so a server-side restriction is defence in depth
rather than a functional requirement. If you want it:

```python
_IT_CATEGORIES = {"electric asset", "it/communication"}

if user.norm_role == "IT_TECHNICIAN" and category.lower() not in _IT_CATEGORIES:
    raise HTTPException(
        status_code=status.HTTP_403_FORBIDDEN,
        detail="IT can only add Electric Asset or IT/Communication items",
    )
```

Note it would also block IT from `PUT /mt-machines/{asset_id}` only if you add the
same guard there — the app doesn't call PUT for this role today.
